# finding-severity

1 つのレビューが出したすべての指摘（必須修正・推奨修正・質問・確認事項・nit）を対象に、対応すべきかを判断し、判断結果を対応リストとして出力する。指摘の出所（どのレビューの、どの報告か）を名指すのは消費者側の責務で、判断を確定した後の適用・終了も消費者が定める。

## 判断基準

- **必須修正**: 原則すべて対応。明らかな誤指摘・前提誤りがある場合のみスキップ
- **推奨修正**: 改善効果と誤指摘リスクを比較し対応可否を判断
- **質問・確認事項**: ユーザーの意図確認が必要なものは対応せず、レビュー出力に残す。コード読解で答えが明確なもののみ対応
- **nit**: 対応は任意。低リスクで機械的に適用できるものだけ対応してよい。見送りは下記写像のとおり `finding-triage` の対象外で、「対応しない指摘」への列挙も不要（レビュー出力には残っている）

## 見送り判断の検証

必須修正・推奨修正を見送る場合に必須。`finding-triage` の規律で検証してから見送りを確定する。写像: 必須修正・推奨修正 = 「対応が期待される指摘」、nit・質問・確認事項 = 対象外（質問をユーザー確認に残すかは上記の判断基準に従う）。

## テストコード変更時の留意点

`test-implementation` 準拠:

- 過剰なモック追加は避ける
- テストskipでの誤指摘回避は禁止
- 重複テスト・意味のないテストは追加しない

## 対応リストの出力

判断結果を以下の形式で出力する:

```markdown
### 指摘事項の対応判断

#### 対応する指摘
- <ファイル>: <指摘概要>

#### 対応しない指摘
- <ファイル>: <指摘概要> — <対応しない理由>（検証根拠: <実行したgrep・再読した箇所・確認したIssue記述等>）
```

検証根拠は必須修正・推奨修正の見送りで必須（`finding-triage`「検証根拠の記録」の内容をここに書く。質問・確認事項を「ユーザー確認が必要」として残す場合は不要）。
