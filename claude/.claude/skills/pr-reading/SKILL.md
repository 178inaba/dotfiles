# pr-reading

PR が何をしようとしていて何を変えたのかを、durable な記録から組み立て直す手順。実装したセッションでは意図が文脈に残っているため省いても成立するが、日を跨いだ実行では「見たことのない設計」を判断・要約することになり、失敗が silent になる（意図的な決定を覆す修正を受け入れる／引用できない根拠で押し返す／存在しない意図をブリーフに書く）。

呼び出し側は起動時に次の4つを名指す（値は「消費者ごとの割り当て」）:

- **container**: Issue の入れ物となる配列と、その読めなかったものを説明する `warnings[]`。**どちらも呼び出し側が名指したものだけを使い、文書側に同名の配列があっても引かない**（`--issue` 等で container を差し替える消費者では、文書側の配列は照合すべきでない別の Issue 集合になる）
- **文書**: `pr.body` と `commits[]` を読むファイルのパス
- **差分・コミットの取得元**: その文書か、呼び出し側が指定するローカルコマンドか。文書が唯一の出典で、ローカルを名指せるのは文書がその変更を運べない状態（PR がまだ無い、文書の差分より先のローカル commit がある）に限る
- **報告先**: 「報告」の1文をどの出力に載せるか

## ステートレス

判断・ブリーフに達するすべての実行で読む。実装したセッションでも、日を跨いだセッションでも、確認のみのモードでも、繰り返し実行の各イテレーションでも同じ。フラグ・実行モードは省略の理由にならず、「このセッションは既に読んだ」という自己申告も理由にならない。省略が成立するのは、呼び出し側が持つゲートが読解より前に実行そのものを終わらせる場合だけで、それを決めるのはそのゲートであってこの手順ではない（どの消費者がゲートを持つかは「消費者ごとの割り当て」）。

**compaction が挟まったら**: 読解の後・判断の前に起きた場合は、本手順をもう一度だけ実行する。差分を読み終える前に起きた場合と、2回目の compaction が起きた場合は、1回の実行で保持できる規模を超えているとして停止し、その旨を報告する。要約で代替しない（大きすぎる変更は PR の分割で解く）。

## 順序

意図 → 変更の順に読む。変更を先に見ると、意図の読みが「その変更を裏付ける根拠探し」に寄り、変更が触れていない決定を見落とす。

1. container の各要素の `body`、続いて `comments[].body` を古い順
2. その `parent.body`、続いて `parent.comments[].body` を古い順（親が横断ルールを持ち Sub がそれに縛られることは `github-sub-issues`「運用規約」が定めている。確定事項が本文ではなく議論に残っていることがあるため、コメントも読む）
3. `pr.body`
4. `commits[].message` を古い順
5. 差分（「差分全体」）

呼び出し側がローカルの取得元を名指した状態では、コミットメッセージも差分と同じ取得元から読む。PR そのものが無い状態では文書自体が無く、`pr.body` は読むものが無い。

会話（レビュー本文・行コメント・通常コメント）をこの順序のどこに置くかは呼び出し側が決める（「消費者ごとの割り当て」）。

## 差分全体

差分にサイズの閾値は無い。

- 差分を Read で読み、1つの Read window に収まらなければ `offset` を増やして末尾まで読む。読む量を減らすための要約・サブエージェントへの委譲・前回読んだ内容の使い回しはしない。一部を読んだ時点で結論を出さない
- 除外はサイズではなく種別のみ。`diff.files[].generated: true` のファイルは hunk を読み飛ばし、**読んだ件数には数えず**、パスと `additions` / `deletions`（binary は null）だけを報告に載せる（生成物かどうかを決めるのはリポジトリの属性であってモデルではない）。読み飛ばす範囲は、その `b/<path>` を持つ `diff --git` の見出し行（rename では a 側が違うので b 側で引く）から次の見出し行まで
- ファイルごとの統計は「全部見たか」の事後確認に使い、事前に読み飛ばすファイルを決めるためには使わない
- 生成物の印を持たない取得元では、差分全体を読む

**網羅の確認**: 読みながら現れた `diff --git a/... b/...` ヘッダを控え、読み終えてからファイル一覧（`diff.files[]` の `path`。rename / copy は `previous_path` も）と突き合わせる。説明できないファイルが残ったら、確実に読んだ最後の `diff --git` ヘッダから読み直す。

**差分側の縮退**:

- 差分ファイルが無い → 文書が不整合。停止して、その文書を書いたコマンドの取り直しを促す
- ファイルが空でファイル一覧も空 → commit が差し引きゼロの PR。その旨を述べ、読むものが無いとして続行する

## 読めない Issue

読めなかったものは報告して続ける（黙って落とさない）。要件の突き合わせにも押し返しの引用にも使わない:

- `body` が null の container 要素 → `warnings[]` の該当行を添えて、読めなかった Issue として報告し、その Issue を要件の突き合わせから外して続行する
- `comments_truncated` が真の要素（親のコメントも同じ） → 運ばれた範囲まで読み、打ち切りを報告に載せる。再取得の要否は呼び出し側が決める

## 報告

差分を末尾まで読んだこと・読んだ件数（ファイル一覧の件数から generated の件数を引いた数）・generated として飛ばしたパスと行数を、呼び出し側が指定した報告先に出す。

## 消費者ごとの割り当て

各消費者が名指す値と、この手順の前後・途中に挟む自分のステップ。

| 消費者 | container / 文書 | 差分・コミットの取得元 | 報告先 | 呼び出し側が持つもの |
|---|---|---|---|---|
| `review-response` | `linked_issues[]` / `ccx pr context` の作業ドキュメント | 文書（`ahead_own` でも文書側。理由は同スキルが持つ） | 「対応対象の指摘」「反応待ちスレッド」より前 | 判断対象の有無の確認によるゲート（「ステートレス」の唯一の省略経路）、会話を読解の**後**に置く順序とその例外、`comments_truncated` の上限引き上げ |
| `deep-review` | `ccx pr prepare-review` の `issues` と同出力の `warnings[]` / `context_path` | 状態で分岐し、文書とローカルの両方を取りうる（分岐の正は同スキルが持つ） | 「レビュー結果出力」の「確認した内容」 | 「PR コンテキストの読了」を container より**前**に置く順序、`pr_exists` / `freshness.status` による取得元の選択、container の読解の**直後**に挟む `ccx issue tree` と役割分担、Issue の打ち切りを再取得しない判断 |
| `understand-pr` | `linked_issues[]` / `ccx pr context` の文書 | 文書 | ブリーフの変更内容 | ブリーフの構成（配線は 178inaba/dotfiles#166） |

`issue-handle` は消費者ではない。実装したセッションで動き、意図が文脈に残っているため組み立て直す必要がない（178inaba/dotfiles#163 の Out of scope）。
