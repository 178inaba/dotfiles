# /html-report

直近の会話または指定テーマを、視覚的に整理した自己完結 HTML ページにまとめてブラウザで開く。「いま理解して比較して判断する」ための読み捨てページを作るのが目的で、Git 管理する文書や GitHub 投稿（Markdown 描画面）には使わない。

## 使用方法
```
/html-report                  # 直近の会話をページ化
/html-report <テーマ>          # テーマを説明するページを作成
/html-report --eli5           # 直近の会話を、その話題を知らない読者向けにページ化
/html-report --eli5 <テーマ>   # そのテーマを知らない読者向けに説明するページを作成
```

## 実行内容

1. **内容の決定**: 引数なしなら直近の会話からページ化する価値のある内容（結論・比較・一覧・構造）を抽出する。引数ありならそのテーマを説明する内容を組み立てる。会話に材料が無ければページ構成に必要な最小限の調査で補い、本格的な調査が必要そうなら先にユーザーに確認する
   - **読者**: 既定の読者はユーザー自身（判断するために読む）。`--eli5` はテーマ引数ではなくフラグで、単独指定なら直近の会話を対象にする。指定時は読者を「その話題を全く知らない人」に固定し、大きな絵と少ない文字数を優先する（細部より全体像、専門用語は避けるか噛み砕く）。フラグが無くても、依頼が読者を明示している場合（「非エンジニアに説明して」「子供でも分かるように」「初めての人向けに」等）は同じ扱いにする
2. **HTML 作成**: scratchpad ディレクトリ（無い環境では `mktemp -d`）に自己完結 HTML を書く。読み捨て前提のため、作業リポジトリ内には置かない
3. **開く**: `open <path>`（macOS）/ `xdg-open <path>`（Linux）
4. **完了報告**: ファイルパスとページ構成の要約を提示し、「残す場合は移動先を伝えてください（例: デスクトップ）」と案内する（scratchpad は保持が保証されない一時領域のため）

## HTML の作成規定

- **自己完結**: CSS/JS はすべてインライン、外部リクエスト（CDN・Web フォント・画像 URL）なし。ローカルファイルを開くだけで完全に表示されること
- **ライト/ダーク両対応**: 配色は `:root` の CSS 変数に集約し、`@media (prefers-color-scheme: dark)` 内の変数上書き1ブロックだけで切り替える（ルールセット全体の二重生成を避ける）
- **構造で見せる**: 長文の羅列にせず、内容に合う表現を選ぶ — 比較はカードグリッド/表、重大度・判定は色分けバッジ、処理フロー・構造は flexbox/grid のボックスと矢印文字による HTML/CSS 表現を第一候補にし HTML/CSS で表現しにくい形状に限りインライン SVG（SVG は描画結果を確認できず崩れやすい）、長い内容はタブ・折りたたみで分割
- **対話要素は理解を助ける場合のみ**: タブ切り替え・ソート・スライダー等は読者の比較・判断に効くときだけ入れる。飾りの JS は入れない
- **出典を残す**: 調査系の内容は参照リンクをフッターに列挙する
- **言語**: ページの言語は会話の言語に合わせる
- **ELI5 モードでも緩めない**: 上記の規定は `--eli5`（および依頼が読者を指定している場合）にも同じく適用する。絵は HTML/CSS のボックス・配色・余白・絵文字で作るのが第一候補で、インライン SVG の制限も、調査系での出典フッターもそのまま守る
